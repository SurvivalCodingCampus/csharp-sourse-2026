#비동기 처리
    동기: 앞 작업이 끝난 후 다음 작업 실행
    비동기: 기다리는 동안 다른 작업 가능
    async: <await>를 사용할 수 있게 표시
    await: 작업 완료 후 다음 줄부터 실행
    ContinueWith: 작업 완료 후 실행할 콜백 연결 
          ㄴ> 여기서 📌예외처를 try catch으로 못함 || 🌟❇️대신에 asyn , await(둘은 짝임): 순서방식을 예측가능함()::  순서방식을 예측가능함(await가 있어서 비동기 이지만 동기처럼 작동됨)
    I/O: 파일·인터넷처럼 비동기 처리에 적합한 작업(응답을 기다리는 동안 프로그램을 멈추지 않고 실행하는 방식)

#함수 호출

   Delegate: 함수를 저장하는 타입
   Event: 특정 상황 발생을 다른 객체에 알림
   Invoke: 저장된 함수나 이벤트 실행


#여러 작업 처리

   Concurrency (동시성): 시간을 쪼개서 '작업을 번갈아 실행'(싱글코어) > 동시 진행되는 것처럼 보임 👁️👁️
   Parallelism (병렬성): 여러 코어에서 실제 동시 실행
   Task.WhenAll: 여러 작업이 모두 끝날 때까지 기다림
   Thread: 여러작업을 동시에 처리하기 위해 스레드를 여러개 만들어 실행하는 방식(컴퓨터에서 작업을 여러개 가능한 것(옛날에는 MP3들으면 노래만 들어야 했음))

   세마포어: 여러 작업이 공유 자원에 동시에 접근할 수 있는 최대 개수를 제한
       ㄴ>잘못 사용했을때 Deadlock발생(발생의 조건, 아래 확인)
       상호 배제 (Mutual Exclusion): 한 한번에 한 프로세스만 자원을 사용할 수 있음.                            
       점유와 대기 (Hold and Wait): 자원을 하나 가진 상태에서 다른 자원을 기다림.                            
       비선점 (No Preemption): 다른 프로세스가 가진 자원을 강제로 빼앗을 수 없음.                            
       순환 대기 (Circular Wait): A는 B의 자원을, B는 A의 자원을 기다리는 대기 고리가 형성됨


#작업 제어

   Semaphore: 동시에 자원을 사용하는 작업 수 제한
   Deadlock: 작업들이 서로 기다리며 멈추는 현상
   Coroutine: 실행을 잠시 멈췄다가 이어서 실행하는 함수
