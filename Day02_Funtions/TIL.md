# Day 02 TIL

## 학습 주제

`C#의 람다식과 함수형 프로그래밍의 기본 개념`을 학습했다. 함수를 값처럼 전달하는 방식과 LINQ의 고계 함수가 데이터를 처리하는 흐름을 중심으로 살펴봤다.

## 학습 목적

람다식, 델리게이트, 고계 함수의 관계를 이해하고 `Where`, `Select`, `Any`, `Aggregate` 같은 LINQ 함수를 상황에 맞게 선택하는 기준을 익히는 것이 목적이다.

## 핵심 개념

- **1급 객체**는 변수에 대입하거나 함수의 인자로 전달할 수 있는 객체다. C#에서는 델리게이트를 통해 메서드나 람다식을 값처럼 다룰 수 있다.
- **델리게이트**는 메서드를 참조하는 타입 안전한 형식이다. 입력과 출력 형식이 맞는 함수를 저장하거나 전달할 수 있다.
- **람다식**은 이름 없이 함수의 입력과 동작을 간결하게 표현하는 문법이다.
- **익명 함수**는 이름이 없는 함수이며, 람다식은 익명 함수를 표현하는 대표적인 방법이다.
- **고계 함수**는 다른 함수를 인자로 받거나 함수를 결과로 반환하는 함수다. LINQ의 여러 연산자는 조건식이나 변환식을 람다식으로 전달받는다.
- **함수형 프로그래밍**은 자료 처리를 함수의 계산으로 표현하고 가변 데이터 사용을 줄이는 방식이다. C#은 객체지향과 함수형 특징을 함께 제공한다.

| 구분 | 역할 | LINQ 예시 |
| --- | --- | --- |
| `Where` | 조건에 맞는 요소를 필터링한다 | 2011년 거래만 선택 |
| `Select` | 각 요소를 다른 값이나 형태로 변환한다 | 거래에서 거래자 이름 추출 |
| `Any` | 조건을 만족하는 요소의 존재 여부를 확인한다 | 밀라노 거래자 존재 확인 |
| `Aggregate` | 여러 요소를 하나의 결과로 누적한다 | 거래 금액 합산 |
| `ToList` | `IEnumerable<T>` 결과를 목록으로 만든다 | 쿼리 결과 구체화 |
| `ToHashSet` | 결과를 중복 없는 집합으로 만든다 | 도시 이름 중복 제거 |

## 실습 또는 예제

```csharp
var transactions2011 = transactions
    .Where(transaction => transaction.Year == 2011)
    .OrderBy(transaction => transaction.Value)
    .Select(transaction => transaction.Trader.Name)
    .ToList();

Console.WriteLine(string.Join(", ", transactions2011));
```

### 실행 결과

```text
Brian, Raoul
```

2011년에 발생한 거래를 `Where`로 필터링하고, 거래 금액을 기준으로 오름차순 정렬한 뒤 `Select`로 거래자 이름만 추출했다. 람다식이 각 LINQ 연산에 필요한 조건과 변환 규칙을 함수 값으로 전달한다는 점을 확인했다.

## 이해한 내용

람다식은 단순히 코드를 짧게 만드는 문법이 아니라, 동작 자체를 값처럼 전달하기 위한 표현 방식이다. 델리게이트가 함수의 타입을 정의하고, 람다식은 그 타입에 맞는 동작을 즉석에서 작성한다.

LINQ 쿼리는 데이터를 직접 변경하기보다 필터링과 변환 단계를 연결해 새로운 결과를 만든다. `Where`는 원소의 포함 여부를 결정하고, `Select`는 포함된 원소의 형태를 바꾼다는 차이를 이해했다.

또한 LINQ 연산의 결과가 주로 `IEnumerable<T>`이므로, 실제 목록이나 집합이 필요할 때 `ToList()` 또는 `ToHashSet()`으로 변환해야 한다는 점을 확인했다.

## 헷갈렸던 부분

`여러 LINQ 연산 중 무엇을 먼저 적용`해야 하는지 결정하는 과정이 헷갈렸다. 문제에서 대상, 조건, 정렬 기준, 추출할 값, 최종 결과 형태를 먼저 구분하면 연산 순서를 정하기 쉬워진다.

| 확인 질문 | 선택할 연산 |
| --- | --- |
| 어떤 요소만 남길 것인가? | `Where` |
| 어떤 값으로 바꿀 것인가? | `Select` |
| 어떤 순서로 나열할 것인가? | `OrderBy`, `OrderByDescending` |
| 중복을 제거할 것인가? | `Distinct`, `ToHashSet` |
| 조건을 만족하는 값이 존재하는가? | `Any` |
| 여러 값을 하나로 줄일 것인가? | `Aggregate` |

`IEnumerable<T>`가 반환되었다고 해서 즉시 계산과 저장이 끝난 것으로 생각하기 쉬운 점도 주의해야 한다. 열거 가능한 쿼리와 실제로 구체화된 `List<T>`의 차이를 더 복습할 필요가 있다.

## 다시 볼 포인트

- 델리게이트는 함수의 타입을 정의하고, 람다식은 전달할 동작을 표현한다.
- `Where`는 필터링, `Select`는 변환이라는 기준으로 구분한다.
- LINQ 문제를 풀기 전에 대상, 조건, 정렬, 변환, 결과 형태를 순서대로 분리한다.
- `IEnumerable<T>`, `List<T>`, `HashSet<T>`의 역할과 변환 시점을 다시 확인한다.
- `Any`와 `Aggregate`처럼 반환 결과가 컬렉션이 아닌 연산의 용도를 예제와 함께 복습한다.
