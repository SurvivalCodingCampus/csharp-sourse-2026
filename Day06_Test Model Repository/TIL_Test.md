Test이론
방법: 
수동 테스트(print). 단위 테스트(test 코드), 통합 테스트(UI test, Intergration test)
화이트 테스트(내부 구조와 동작에 중점), 블랙박스 테스트(소프트웨어의 내부 구조를 무시, 최근 하드웨어 성능 좋아서 보통 블랙박스 테스트함.)
Unit 테스트: 특정 모듈이 의도한 대로 잘 작동하는가를 테스트하는 가장 작은 단위의 테스트. 모듈 = 메서드, 기능
- 장점: 신속한 피드백, 조기장애 감지, 안전한 코드 리팩터링, 안정적인 개발 속도
- 조건(FRIEND): Fast, Reliable, Independent, Ease of Maintenance, Nearly compacted code, Dependencies should be less
- 테스트 케이스: 동등분할, 경계값 분석
- 필요한 상황: DB: 스키마 변경, 모델 클래스 변경 시/ Network: 네트워크 연결이 정상, 미연결/데이터 검증: 예측 데이터에 대한 처리 확인, 잘못된 데이터 사용 대비
TDD(Test Driven Development): 테스트 중심으로 개발하는 방법론
- 테스트 코드 먼저 작성 후 테스트 성공하도록 코드 수정
Test Double: 테스트를 진행하기 어려운 경우에 테스트가 가능하도록 만들어주는 객체
- Mocks(범용적),  Dummies, Stubs, Spies, Fakes
