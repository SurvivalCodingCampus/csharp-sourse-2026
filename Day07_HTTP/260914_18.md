## 📝 과제 정보

- **교육 주제**:HTTP
### **HTTP**

### 1. 웹 자원 식별 (URI / URN / URL)

* **URI:** 자원을 식별하는 최상위 개념
* **URN:** 자원의 고유한 이름
* **URL:** 자원의 위치(접근 경로)


### 2. 데이터 교환 및 통신 프로토콜

**JSON**

* 서버-클라이언트 간 표준 데이터 교환 Format
* 가볍고 읽기 쉬우며 문자열 직렬화/역직렬화가 용이

**HTTP / HTTPS**

* **특징:** 웹 문서 및 멀티미디어 전송용 무상태(Stateless) 프로토콜
* **데이터 전송:** 바이너리는 Base64 또는 Multipart 활용
* **HTTPS:** HTTP + SSL/TLS 보안 계층 추가

**Stateful TCP (소켓 통신)**

* **연결 지향:** 1:1 전용 연결 유지, 장애 감지 가능
* **효율성:** 바이너리 전송 및 작은 패킷 크기로 속도가 빠름
* **주의점:** 1개 소켓을 공유하므로 요청 식별자 및 타임아웃 처리를 직접 구현

**TCP vs UDP**

* **TCP:** 연결 지향, 신뢰성 보장, 흐름 제어 제공
* **UDP:** 비연결형, 빠른 속도, 신뢰성 미보장, 멀티/브로드캐스팅 지원

### 3. HTTP 메서드 & 헤더

**HTTP 메서드**

* **GET:** 데이터 조회 (Body 미사용, 쿼리 파라미터 활용)
* **POST:** 데이터 생성/제출 (Body에 데이터 포함)
* **PUT / PATCH:** 전체 수정 / 일부 수정
* **DELETE:** 데이터 삭제

**주요 요소**

* **Content-Type:** JSON 전송 시 `application/json` 지정
* **상태 코드:** `200`(성공), `400`(요청 오류), `404`(자원 없음), `500`(서버 오류)

### 4. 상태 관리 & RESTful API

**상태 유지 (State Management)**

* **Web:** Session(서버 저장) + Cookie(클라이언트 저장)
* **Mobile:** Local Storage / SharedPreferences 등 자체 저장소 활용

**RESTful API**

* REST 아키텍처 스타일을 따르는 API 설계 규격
* HTTP URL(자원), Method(행위), JSON(표현)을 조합하여 구성

**언어별 HTTP 클라이언트**

* **C#:** `HttpClient`
* **Unity:** `UnityWebRequest`
