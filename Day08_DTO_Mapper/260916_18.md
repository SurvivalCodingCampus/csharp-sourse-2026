## 📝 과제 정보

- **교육 주제**: HTTP_DTO_Mapper


---

### 1. 기본 통신 아키텍처 & 데이터 흐름

```
Remote DB ──(JSON 수신/HttpClient)──> DataSource ──(역직렬화)──> DTO
                                                                 │
Repository <──(도메인/비즈니스 로직)── Model <──(Mapper 변환)────┘

```

* **Remote DB:** 원본 데이터 저장소
* **DataSource:** HttpClient 기반 데이터 수신 및 단순 역직렬화
* **DTO:** 서버의 JSON 구조를 그대로 받아내는 중간 객체
* **Mapper:** DTO를 앱 안전한 Model로 변환하는 유틸리티
* **Model:** 앱 내부에서 실제 사용하는 **Non-nullable** 중심 도메인 객체
* **Repository:** 데이터 가공, 분류 및 비즈니스 로직 처리

---

### 2. 서버 통신 문제와 DTO가 필요한 이유

**서버 통신 주요 이슈**

* API 변경으로 인한 필드 누락/제거
* 서버 장애 시 예외 응답(Null 또는 구조 변형) 발생
* 클라이언트-서버 간 버전 불일치

**DTO 도입 목적 (방어적 설계)**

* **오류 방지:** 잘못된 JSON 응답 시 앱 런타임 크래시(Crash) 방지
* **Null 안전성 확보:** JSON 특성상 Null이 유입될 수 있으므로 DTO에서 Nullable(`?`)로 수신한 뒤, 안전성 검증을 거쳐 Model에 전달
* **선택적 도입:** JSON 규격이 확실하고 예외 가능성이 없다면 DTO 생략 가능

---

### 3. Mapper (변환기)

* **역할:** DTO(데이터) $\rightarrow$ Model(도메인 객체) 변환
* **핵심 기능:**
* Nullable 타입을 Non-nullable 타입으로 전환 (Null Guard/기본값 할당)
* 앱에서 실제 필요한 필드만 추출하여 변환


* **구현 패턴:** static 클래스 기반 **확장 메서드(Extension Method)** 활용 추천
